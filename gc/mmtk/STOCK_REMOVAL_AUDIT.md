# Stock-GC dead-code removal audit

Adversarially-verified audit (118 agents: map → refute-each-candidate → synthesize) of what stock
OCaml GC/runtime code can still be removed from the always-on-MMTk fork. Every item below survived
an adversarial refutation pass; the keep-list is the plausible-but-load-bearing code the refuter rejected.

**~650 removable lines, 76 items ({'low': 57, 'medium': 19}).** The low-risk
independent clusters are being actioned on branch `remove-dead-stock`.

> This audit confirms a substantial second wave of dead stock-GC code beyond ROADMAP #18's prior partial audit: the bulk of #18's already-known items (the EV_C_MAJOR_* phantom spans #R3, the frozen caml_gc_phase no-op branches, the dead caml_mark_roots_stw) are re-confirmed, but the NEW high-value finds not catalogued by #18 are the entire dead minor->major remembered-set machinery (struct caml_ref_table / Ref_table_add / caml_alloc_table / caml_realloc_ref_table), the zero-caller finaliser/oldify helpers (caml_final_do_young_roots, oldify_state, promote_result), the dead opportunistic-major family, and the stale runtime/dune build subsystem. Every item below survived adversarial refutation; the refuter correctly rejected a large set of plausible-but-load-bearing candidates (the EV_* positional-ABI enums, the dependent-memory/Gc.Tweak/Gc.ramp ABI, the shared_heap domain_state offset placeholder, the frozen weak/ephemeron no-op branches, and the generational young-root machinery that #G1 has parked for reuse), so the confirmed list is conservative — zero-caller deletes and write-only/constant-fold dead state, with cross-file or offset-shifting items flagged medium. Net deletable surface is roughly 600-700 lines, dominated by the runtime/dune subsystem (~78) and the remembered-set + opportunistic-major + pacing clusters.
